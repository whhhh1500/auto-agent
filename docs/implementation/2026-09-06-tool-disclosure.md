# 工具按需披露：请求声明、恢复和总成本

本切片补 M24 的实际模型请求验证。当前 `describe` 返回了 schema，但 `Schemas()` 从不在后续模型请求中提供被描述的工具。既有单测直接执行隐藏 ID，不能证明模型协议可调用。

## 设计选择

1. 保持 `DiscloseTools` 显式启用和原有 search / list / describe 协议，不默认替换所有工具目录。
2. 每次模型调用，根据当前已投影/压缩的聊天消息和当前授权快照构造声明：成功 describe 的工具，以及已经有结果的业务工具，最多保留最近 8 个；原有 hot tools 和目录入口仍提供。随后让现有 ContextAssembler 对最终集合计费、裁剪历史。
3. 不增加可变全局目录或会话缓存。从日志投影恢复选择，服务重建/审批恢复不依赖内存状态；旧记录中的 schema 不作为当前契约，始终读取当前快照。消息中不能识别的描述结果、失败 describe 和越权/已移除 ID 不加入声明。截断或摘要掉发现记录后允许重新发现。
4. 不采用“允许模型调用未声明工具”作为兼容策略，也不根据模糊检索自动把多个候选全部暴露。执行授权、Hook、审批和工具预算仍由现有 guarded funnel 执行。
5. 已由宿主注册 `harness.tool.library` 时，保留宿主 runtime，不注入重复入口或截走其调用。这也保留外部目录集成方式。`toollib.Catalog.SetSearcher` 只替换该目录的搜索器，并不会自动替换 core 内置关键词目录，文档必须区分这两条实现。

公共 core 接口不增加。与仅做一次可变 `describe` 记忆相比，无状态投影可恢复，代价是每次扫描当前模型历史；用小量选择上限限制附加 schema 复制，基准测它的实际成本。Schema 变化进入既有最终预算和 trace 估算，不删除持久聊天记录。

## 验收范围

- 先用严格脚本模型复现：describe 成功后，下一次模型请求必须含当前目标 schema；新建 Agent 与日志恢复也适用。
- 覆盖权限撤销、schema 更新、失败/歧义描述、伪造其他工具结果、别名、选择上限和 schema 防御复制；核心预算 gate 不因改动放宽。
- 4 个与 24 个工具的受控任务，同模型、目录、历史、问题和真实业务夹具，只切换披露开关。每个 arm 两轮，会话中途重建服务，累计全部模型输入/输出 token、请求、工具次数、耗时和结果正确性；如披露在小目录更贵，保留实测，不隐藏额外步骤。
- 使用 Gemini 3.8 Flash，严格串行、无自动重试；检查 SQL/HTTP 历史、trace、业务调用效果，并在隔离 SQL schema 清理前导出证据。先离线验证，再只运行新增的真实模型场景。

## 实施与实测结果

本切片已完成并通过定向、全仓与真实模型检查。20 次真实请求中，24 工具的两轮会话总 token 减少 54.89%，4 工具反而增加 50.13%；重建后目标工具继续声明且无需重复发现，两组披露延迟均增加。保留默认关闭和完整反例，未据此猜测通用阈值或自动启用策略。见[实测、逐请求与审计证据](../performance/2026-09-06-tool-disclosure.md)。长期任务、硬重启与跨框架公平对照继续作为整体目标推进。
