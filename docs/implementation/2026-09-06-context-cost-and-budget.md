# 上下文成本、工具预算和可替换估算器

目标：在继续推进整体 Agent 优化的过程中，补齐最终工具声明的预算，减少上下文重复校验成本，并让用量指标可实际导出。本轮不是对整体目标或跨框架优劣的完成声明。

现状基线：`d1e0bb2`。`callModel` 在上下文组装之后才获取工具 Schema；默认 Assembler 无法计入它们。`Assemble` 已校验所有消息，内置估算器又重复校验并序列化参数。OTel 固定指标表缺少内核已发送的三个上下文成本计数器。

选择：在现有 `ModelContext` 增加只供预算使用的最终工具集合；`callModel` 每步取一次 Schema，并将同一集合用于模型请求。应用层 `ContextEstimator` 组合现有 `BudgetEstimator` 与 `EstimateTools`，工具成本使用独立的 required tools 层；它不能被消息裁剪移除，也不能被插件偷偷替换成另一组授权工具。旧自定义 assembler 不必新增返回字段。

与只在 HTTP adapter 超限报错相比，该方案能在模型请求前保留工具预算、裁剪可选旧历史。与把厂商 tokenizer 放入内核相比，该方案保留标准库内核及应用层估算扩展点。默认仍使用保守估算；精确厂商 token 计算应由相应适配器或宿主提供，不把估算值称为账单 token。

优化只对已经过 Request 校验的内置估算器使用私有快速路径；公开 estimator 方法仍校验输入。第三方估算器保留原调用合同和 panic 隔离，不用全局缓存、不借优化放松消息/参数校验。

验收：

- 预算器收到实际发送的工具集合，每步获取一次；插件修改其副本不改变实际发送内容。
- 工具预算使原本能放下的旧历史被合理裁剪；必需工具或当前消息放不下时，在请求上游前失败。
- 自定义估算器实际收到工具层；非法返回值、panic、非法 schema 均拒绝。
- 内置公开/快速估算成本相同，拒绝边界不变；同夹具记录优化前后 ns/op、B/op、allocs/op。
- OTel SDK 的 reader 实际收集到上下文成本指标及准确累加值。
- 全仓及受影响范围 race 回归；真实模型仅串行补验发生变化的工具路径，检查 trace 和持久聊天历史。

后续整体目标仍需独立推进：工具选择/披露的实际 token 成本、长任务摘要与恢复、WASM 资源限制、跨协议/外部执行的实际验收，以及同任务同模型条件的跨框架资源与质量对照。
