## 独立证据核对

六例均通过最终答案和 Session 最终 assistant 答案的精确聚合断言（忽略首尾空白）；实际 fixture inventory 恰好一次、detail 恰好八次，每个目标 ID 一次，工具结果均 OK。每例 3 条出站结构记录与 3 个模型轮次对应，instructions 存在且长度匹配。

本轮原始 JSON 逐例核对：最终 assembler request 限额均为 128,000 / 4,096，组装成功，未丢弃任何上下文组，所有应见结果均完整。Terra 自动样本最终可见结果为 3 个，其余样本为 9 个。这些限额是 adapter 编译配置，未经 provider 原生窗口认证。

审核发现旧测试虽记录这些字段，但 v5/v6 的 4 KiB 成功路径未强制断言额度匹配和结果完整性。因此本轮上述结论来自另行核对原始记录，不能仅从旧 PASS 推导。随后补强测试断言的源码与本轮冻结二进制属于不同版本，应分别保留验证证据。

后续测试修订已加入：请求前拒绝缺失或无效的 adapter 限额；成功后断言实际 assembler request 与 adapter 报告匹配；4 KiB 成功路径要求组装成功、结果完整、零丢弃。定向离线反例覆盖报告器缺失、零窗口和输出等于窗口，`TestLargeDetail` 离线测试通过。此修订不改变生产执行逻辑。
