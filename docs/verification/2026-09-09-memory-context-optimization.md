## 未完成的整体目标

关于轮次和恢复的架构审核：`MaxSteps` 约束普通 Agent 步骤，并不把可选摘要 adapter invocation 算作额外 step。当前 `RollingSummarizer + LlmSummarizer` 每 step 最多一次摘要 invocation 加一次普通 invocation；这不是 HTTP 请求上限，不包括 adapter 内部重试或任意自定义 summarizer。默认泛用 server 使用本地 Extractive，没有摘要模型请求。摘要已报告的 usage 会纳入同一 Run 的后续停止判定，但事后计量阈值不等于调用前预留式费用上限。

Native strict 的公开构造器自行创建 Runtime，目前没有配置 summarizer 的入口；它与泛用 server 的默认摘要组合不同。未来若为 native queued 接入 LLM 摘要，不能直接复用普通 step 的 model attempt identity/gate，否则摘要与回答会争用同一 attempt。需要独立用途的 admission/outcome 与恢复协议，本轮没有实现或宣称支持此组合。

- 新实体、同名跨作用域和无关记录已取得上述开发样本证据；错误/过期记忆与自主语义查询仍需验证。
- 验证更长历史、预算饱和与多轮摘要复用；当前短历史对照不能证明长期信息保留或摊销收益。
- 验证渐进展示是否保留 PTC 可达性并改善自主选择；不能把移除 PTC 菜单的对照直接当作最终实现。

以上属于开发实验，不能替代跨会话持久恢复、错误/过期记忆、冻结留出集或自动策略发布验收。
