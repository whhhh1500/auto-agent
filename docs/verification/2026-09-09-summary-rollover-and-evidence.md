# 重复滚动摘要与失败用量证据

这是开发验收记录，承接[前十五波真实验证](2026-09-09-memory-context-optimization.md)。不代表完整优化目标完成，也不代表厂商原生长上下文窗口或 SQL 恢复验收。

## 第十六波：修复前真实基线

固定 24 个合法合成历史 turn（8 Cedar、16 Orion），共 17,139 个模型可见文本字节，然后执行三个真实 Runtime turn：显式更新随机旧值为新值、连续性确认、询问当前值。最后的问题不含答案。使用生产 ExtractiveSummarizer 和默认 Assembler；测试消息阈值为 3/1，区别于通用 server 的 120/60。只调用普通回答模型，Extractive 不增加摘要模型调用。

模型配置仅读取用户指定文件第 6–9 行。请求模型名为配置身份，不证明网关内部模型身份。固定二进制 SHA-256：`b47196e04db6b89c752067c67cc26918a8d2aaf47f062278bf1cada76e1112c3`。

| 请求模型 | 验收 | 普通模型调用 | 已报告输入/输出 token | 各次摘要字节数 |
| --- | --- | ---: | ---: | --- |
| Terra | 失败 | 3 | 14,133 / 56 | 12,001 → 12,150 → 226 |
| Luna | 失败 | 3 | 14,150 / 57 | 12,001 → 12,150 → 226 |

两例三个 Runtime turn 均完成，模型报告与会话账本总数相等，最终有效摘要投影与持久摘要精确对应，覆盖终点前进；但新值和旧值都不在最终模型上下文，最终及持久答案均未通过。两模型测试退出码均为 1。前两轮提示要求 ACK；该基线二进制未单独断言 ACK 格式，因此不把提示要求当作已验证结果。

根因的本地最小探针：一个 11,950-byte prior summary 加一条短用户更新，当前 Extractive 会保留 prior、遗漏新更新且不返回错误。prior 优先消耗可用空间，接近容量时挤掉 recent user；下一次 prior 过大则整体变为 omission marker。信息丢失发生在调用模型前，不能仅靠要求模型更认真解决。

## 可观测证据补充

- 普通与渐进展示 PTC case 现在记录 fixture provider 的实际 inventory/detail 调用次数，带 observed 标志；不从 Session 事件数推断实际执行次数。
- 工具结果只计固定 `capability_budget_exceeded` 拒绝码。旧波次不回填这些新字段。
- 表达式编译失败可用受限结构扫描记录 composite literal 数组/对象数量；不落盘源程序或值。未观察到与观察到零次分别表示。
- 新增标准库离线汇总器，按二进制/模型/case 分组，计入失败及已报告的部分 usage。摘要实验使用摘要加回答总数；wire/disclosure sidecar 不重复计费。无效/未知记录有跳过计数，重复物理文件拒绝汇总。

汇总器已用第八波摘要和第十五波 PTC 证据复核，分别保留摘要成本与失败样本。它是只读报告工具，不是资源发布门禁；未知用量不等于零费用。

## 修复设计与离线回归

Extractive 先把最近至多四条用户记录渲染一次并计算实际字节预留，再临时收紧 prior-summary 写入预算；连 prior 的 omission marker 也受此限额。之后恢复正常预算并按原顺序写已缓存的 recent records。没有增加模型请求、公共接口或总容量，也不会为计算预留再重复哈希同一条大消息。

旧摘要放不下时仍可能整体标为遗漏，这是明确的质量边界；本次修复保证这些旧摘要不会占用为最新更新预留的空间，不能保证所有历史事实永久保留。多个 recent 总量自身过大时仍按原“可放则放”语义处理。

近上限 prior 挤掉更新的回归、多个 recent 超预算回归与原有 contextassembly 测试通过，race 通过。12 MiB oversized-earlier fixture 的定向基准样本为 1,423 ns/op、4,165 B/op、21 allocs/op；这是跳过大内容的本地样本，不是吞吐量或稳定性能分布证明。

## 第十七波：相同历史的修复后真实复验

历史、packing record、阈值、三个用户提示不变。除生产修复外，测试新增前两轮 result/durable ACK 精确检查、每 run 对应 adapter usage 精确核对、跨 run invocation 唯一检查；没有降低答案要求。固定二进制 SHA-256：`6fdf4f0bb30a71eb7319ce9ca93b1729edfead9551b536931e9bae9d3410b9ed`。

| 请求模型 | 验收 | 普通模型调用 | 已报告输入/输出 token | 各次摘要字节数 |
| --- | --- | ---: | ---: | --- |
| Terra | 通过 | 3 | 12,676 / 55 | 12,001 → 324 → 546 |
| Luna | 通过 | 3 | 12,668 / 32 | 12,001 → 324 → 546 |

两项最终上下文均含 NEW，最终及持久答案正确，前两轮确为 ACK，每 run usage 精确对应且 invocation ID 唯一；测试退出码均为 0。旧值仍可存在于显式 supersedes 的用户记录中，模型正确选择新值；没有把“OLD 必须完全消失”伪造为摘要合同。

相对失败基线，两例报告输入分别少 1,457 和 1,482 token，同时完成了原本失败的任务；普通调用数仍为三，摘要模型调用仍为零。此固定容量回归证明了该缺陷及修复效果，不能推出普遍约 10% 节省、所有历史事实保留或全局最优。

当前源码相关 Go race、vet、modulecheck、Python 汇总器测试及差异检查通过。汇总器对本波两条记录均正确计入三次 invocation，未跳过记录、未报告未知用量。剩余目标包括 PTC 跨样本稳定性、饱和模型上下文选择、SQL 恢复、过期/错误记忆以及资源发布门禁；不以这两项成功关闭整体目标。
