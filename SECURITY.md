# Security policy

Please do not disclose a suspected vulnerability in a public issue or include
secrets in a report. Use the repository's GitHub **Security** tab and create a
private Security Advisory with reproduction steps, affected versions, impact,
and a safe contact path for follow-up. The maintainers will coordinate the
response through GitHub's advisory workflow.

If private advisory submission is unavailable, open a public issue containing
only the neutral statement `Security contact requested`; do not include
exploit details or credentials. This repository does not publish an email
address for security reports.

Supported versions and fixes are recorded in the changelog. Deployments should
also follow the production key, file-permission, credential, and dependency
guidance in `README.md`.
